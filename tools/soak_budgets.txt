# Soak budgets (#424, #407): what was planned, and how the soak measures it. Read by tools/soak_report.py.
#
# One figure per line, whitespace-separated columns; a '#' followed by a space (or ending the line) starts a comment; '#234' is an issue, not a comment.
#   figure     name for the report (no spaces)
#   kind       key       a `fw soak` key (soak1..soak4, firmware/main/soak_line.c); `measure` is the key
#              log       a number in a serial-log line; `measure` is a regex with ONE group (\s for a space)
#              probe     a figure no soak key or log line carries; `measure` names the probe (the report has
#                        no data for it until a later tool, or a CSV column of that name, supplies one)
#              unplanned measured only, nothing was planned; expected `-`
#   measure    see kind
#   expected   a number (two-sided, with tolerance), `<=N` / `>=N` (a limit, one-sided, tolerance `-`) or `-`
#   tolerance  `-`, an absolute number (`2`) or a percentage (`15%`); applies in both directions around expected
#   unit       free label (ms, KiB, B, count, MB/s, s)
#   source     where the plan was written: an issue (#234), a file path or a doc
#   note       everything after the source (optional)
# Operators: `<=N` `>=N` `<N` `>N` are one-sided limits (tolerance must be `-`); a plain number is two-sided with a
# tolerance. Flags: ok; over / under (two-sided figures only; `under` can mean the feature is not running); breach (a
# one-sided limit violated, either direction); unplanned; no data. The run fails on over, under, breach and on
# `no data` for a `key` figure; `unplanned` and `no data` for probe and log figures are shown, not failed.
# Probe names are PLACEHOLDERS: no tool emits them yet. A source of `inferred` means no written plan: 0 (or the
# figure) is the working expectation, to be confirmed by the first soak.
#
# figure kind measure expected tolerance unit source note
